# 项目大纲

## 项目背景

学生和研究者经常需要整理来自不同学科、不同类型的论文和研究资料。计算机科学论文可能强调方法、实验和 benchmark；社会科学论文可能强调研究问题、理论框架和证据来源；人文学科论文可能更重视核心论点、文本材料和解释路径。

LitFolder QA（文献资料夹问答系统）希望把这些资料先整理成本地可维护的文献资料夹，再逐步扩展为基于来源的问答系统。

## 项目动机

本项目不把论文只看作 PDF 文件，而是把每篇文献看作一个带结构信息的研究资料条目。用户可以先手动维护文献信息，后续再加入文本抽取、来源追踪、问答和多文献检索。

## 目标用户

- 需要整理跨学科文献的学生。
- 正在写课程论文、综述、开题报告或 Related Work 的研究者。
- 需要保存论文论点、证据来源和个人笔记的阅读者。
- 想构建一个适合作为简历项目的本地文献管理与 QA 应用的开发者。

## 要解决的问题

- 文献资料分散在 PDF、笔记、链接和文件夹中，难以统一整理。
- 不同学科论文结构不同，单一字段很难表达研究问题、核心论点和证据来源。
- 普通 PDF Chatbot 容易只围绕单个文件问答，缺少长期积累的本地资料夹。
- 后续多文献问答需要明确来源，避免无证据回答。
- 研究脉络整理、文献对比和 gap 分析需要先有结构化文献库。

## 主要使用场景

- 用户添加一篇计算机科学论文，记录方法、贡献、benchmark 和局限。
- 用户添加一篇社会科学论文，记录研究问题、理论论点和证据来源。
- 用户添加一篇人文学科论文，记录核心论点、文本材料和解释路径。
- 用户按年份查看某个研究方向的发展。
- 用户后续针对单篇文献提问，并要求回答标注来源。
- 用户后续选择一个资料夹，生成文献对比或研究脉络摘要。

## 和普通论文 Chatbot 的区别

- 普通论文 Chatbot 通常以单个 PDF 为中心；LitFolder QA 以本地文献资料夹为中心。
- 普通论文 Chatbot 常直接进入问答；LitFolder QA 先强调文献结构化整理和来源字段。
- 普通论文 Chatbot 多面向理工论文；LitFolder QA 预留多学科论文类型。
- 普通论文 Chatbot 常忽略来源可追踪性；LitFolder QA 后续问答会围绕 evidence source 和 source summary 展开。
- Timeline 不再是唯一核心，而是后续研究脉络整理的一种视图。
